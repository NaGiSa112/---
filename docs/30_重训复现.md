# 重训复现验证（2026-11-18）

> ⚠️ **本文部分数字已更正（2026-11-18 22:0x）**：早先引用的 valid AUC 是逐图口径，官方口径为检查级宏平均；六模型配置实测 711.50 MB 超限；
> “训练不可按位复现”的结论已撤回（该轮重训同时改了 batch / 缓存 / drop_path / 端点）。
> 详见 [审阅更正_2026-11-18.md](审阅更正_2026-11-18.md)。

用 2026 赛季最终版的**完全相同配方**重训三个 Tiny 种子，验证整条链能否复现。

**结论：能复现，但不是按位复现。** 三个种子的最优轮次与历史一致（或差 1 轮），
融合后 valid AUC 差 **−0.0010**，提交文件类内排序相关 **0.998**。

| 指标 | 值 |

判定不一致的比例（1%–3%）来自**阈值附近的自然翻转**：概率差 0.01 就足以让个别 study
跨过阈值，这是权重不同导致的必然结果，不是流程错误。

**结论：可用于替换**（排序相关 > 0.99）。若要正式替换，应按配对 bootstrap 重新确认，
而不是看单次绝对 AUC。

## 五、为什么不是按位复现

`src/cxr/train.py` 的 `set_seed()` 只设了：

```python
torch.manual_seed(seed)
torch.cuda.manual_seed_all(seed)
```

**没有**设 cuDNN 的确定性开关，所以每次训练 cuDNN 会选择不同的卷积算法：

```python
# 若需严格复现，补上这三行（代价约 5–15% 速度）
torch.backends.cudnn.deterministic = True
torch.backends.cudnn.benchmark = False
torch.use_deterministic_algorithms(True, warn_only=True)
```

对比之下，**推理侧是设定确定性的**（`cudnn.benchmark=False` + `deterministic=True`），
所以交付包内的代码重算能与 `submission.csv` **逐字节相同**（SHA-256 一致）。

> 这正是要区分的一句话：**能复现交付结果 ≠ 能复现训练过程。**

## 六、对复盘的三条补充结论

1. **同一配方重训的波动（均值 −0.0014，最大 −0.0040）大于大多数被判定"有效"的改动
   （0.001–0.003）**。这解释了为什么赛季内所有结论都必须用配对 bootstrap，
   而不能比较单次绝对 AUC。
2. **重训版在 valid 上并未变差**（−0.0010），说明赛季最后一周选择的三 Tiny 配置是稳的，
   不是靠某次幸运的随机数。
3. **训练可复现的成本很低**：加三行确定性开关即可从"±0.002 波动"变成"按位一致"，
   代价是 5–15% 训练速度。若新一轮需要严格对比实验（例如 A/B 同一改动），建议一开始就打开。
