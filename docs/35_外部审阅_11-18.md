# 国赛冲刺方案可行性审阅

日期：2026-11-18。审阅对象：`33_方案评审包_11-18.md`。本次核查了本地训练配置、源码、历史实验报告，并以 CPU 重新计算已有验证集提交文件的检查级 AUC；没有启动训练或 GPU 推理。

## 结论

单卡、13天完成一轮有控制的改进和最终交付，算力上可行。原方案需要先修正评估和实验前提，再执行候选筛选。现有材料不足以支持各项预期涨幅，也不足以把重训差异归因于随机性。

建议保留三项主工作：**基准审计、无泄漏的配对验证、少量有证据的候选**。优先复查现有跨架构模型；对称差分仅作为通用表示探索；暂缓类别4↔8目标混合、高维后处理和双尺度双分支。

用户本次已确认：**目前只有推定的数字类别与疾病名称映射，没有官方确认。** 因此本报告使用“类别1/4/8”等数字称呼，不把疾病解释作为已知事实。

## 一、必须先改正的前提

| `runs/orig_valid.csv` | 859 | 0.8251945484 | — |
| `runs/retrain_valid.csv` | 859 | 0.8237508312 | −0.0014437172 |

### 2. 这轮重训改变了实际配方，不能用来估计纯随机波动

| 项目 | 历史部署模型 | 本次重训 |
|---|---|---|
| seed43 batch | 12 | 16 |
| Tiny实际最大drop path | 0.10 | 0.15 |
| 训练缓存 | `cache_raw512`，完整解码后缩放 | `cache_dir=""`，默认缓存含draft解码 |
| seed44端点 | 固定last12 | 部署重训best |

历史42/43配置虽然写过0.15，但旧源码仅修改没有实际作用的 `drop_path_rate`；现源码真正修改 `StochasticDepth.p`，因此同一配置文本不代表相同正则。历史44明确使用0.10。

默认缓存抽查4行，与当前draft路径一致；与完整解码再缩放的像素最大差分别为145、38、30、14。当前历史 `cache_raw512` 目录已不存在，需按明确协议重建，不能直接沿用默认缓存。

`set_seed()` 实际也设置Python和NumPy种子，原文“只设torch”不准确。缺少确定性设置确实会影响严格复现，但在以上变量未控制前，不能把差异都算作cuDNN波动。逐epoch的最大差也不是独立重复训练的方差估计。

修正顺序：固定源码版本及实际配置→固定缓存像素协议和批次→固定端点→再做相同seed重复实验。确定性设置还需覆盖DataLoader和相关CUDA算子；`warn_only=True`允许非确定性算子继续运行，不能承诺加三行便跨环境按位一致。[PyTorch 2.9复现说明](https://docs.pytorch.org/docs/2.9/notes/randomness.html)

### 3. 疾病名称映射未经确认，针对病名设计的依据应撤回

`src/cxr/config.py:51–53` 已注明类别名称是按常见排序作的假设，用户本次确认尚无官方映射。

- 类别1的弱表现是真实可测的，但不能据此称它是“肺不张问题”。
- 对称差分可以作为通用图像表示试验，不能预期它专门改善类别1。
- `P(类别8|类别4)=0.529`只能说明标签共现，不能证明两类临床连续或互为错标。**不建议在此依据上互混监督目标。**
- 热力图、人工诊断和报告均应标注“数字类别；病名未核实”，避免用假定解释支撑下一轮假设。

### 4. test-like调参路线应停用

`tools/patient_structure_impact.py:110–126` 读取test患者检查次数，构造目标分布权重；158–163行据此选最优shrink。按现有存档规则第5/6条及补充说明七，这已把测试集汇总信息用于参数选择，不能作为后续选模口径。

替代方案：检查级macro-AUC为主；患者等权、AP/PA、单/多检查、检查次数区间作为诊断或压力测试。分组和任何权重都只由train/valid预先定义，评估工具不读test。

0.7780也不是test AUC的无偏预测。仅重加权检查次数，无法证明标签和预测在各次数组内跨split同分布；不能据此断言“valid系统性高估test约0.05”。现实现中的分箱比例还是患者数比例，并非注释所称的study数比例。

新一轮 `00_规则` 目前未见新规则正文；本项按现有官方存档判断。新阶段规则发布后应核对差异。

### 5. “45名有效患者”和最小可测差异的解释过强

`(Σn)²/Σn²=45.1`描述study等权下患者权重的集中程度；它没有估计类特异的患者内相关、正负样本构成及AUC方差，不能直接等同“ROC-AUC功效只有45名患者”。228名实际患者仍应报告。

绝对AUC的宽区间，也不能推出两个相关模型的配对ΔAUC需要超过0.168才可检测。配对误差的方差可以小得多。OOF会增加样本覆盖，但SE=0.011、最小可测0.03应改为待实测，不能按阳性患者数比例直接承诺。

单类AUC提高0.05，对10类宏平均贡献0.005，即线上百分制的**0.5分**；若证据可靠，这值得争取，不应因绝对AUC区间较宽而否定。

## 二、怎样把五折OOF真正做成可用的评估

### 1. 冻结患者折表，分离划分seed和训练seed

当前 `patient_fold_split()` 使用 `cfg.seed` 划分患者，换训练seed会同时换折，不能称相同数据上的配对复核。先保存唯一患者fold表，后续训练种子只控制训练随机性。

使用train内患者标签向量、检查次数区间和主要体位做近似均衡；一个患者的全部study留在同折。不按test的分布反向调整折比例。多标签均衡需单独实现或验证，不能直接把多标签矩阵交给仅支持单目标分层的工具。

### 2. 隔离整条训练来源，尤其教师

直接沿用 `teacher_soft_full_a.csv` 会使新的外层OOF被污染：教师曾在全train上训练，见过外层留出患者。只筛选软标签CSV中的训练行，不能消除这种间接泄漏。

有两条可行路线：

1. **快速筛查**：baseline和candidate均不使用KD，用同一折、seed、预算、固定last12比较。结论只用于该代理配方；有希望后必须回到实际KD配方确认。
2. **完整确认**：每个outer fold的教师只能使用outer-train，重新生成折内软标签，学生再训练。教师初始化也不得来自见过outer-holdout的本队全量模型。

全train训练的B3同样不能参与train-OOF融合评估；需要折匹配B3，或明确该阶段只比较Tiny代理，最终在尚未并入训练的官方valid上确认完整部署。

患者标签平滑当前在切分后的dataset内计算，患者整体切分时可保留。任何从全量已训练最终模型出发的“第0步等价”微调，也不能冒充干净的外层OOF。

### 3. 外层留出折不参与挑epoch

当前训练每轮看holdout并选择 `best.pt`，再拼OOF，会引入选模偏差。建议预注册固定12轮的 `last.pt`；需要早停时，用outer-train内部的inner split，outer-holdout仅作确认。

OOF用于拟合10个shrink后，在同一OOF上报告“最优提升”，仍是样本内收益。需在内层/调参部分拟合，在外层/确认部分评估。OOF本身不免除后处理的过拟合。[Cawley与Talbot关于选模偏差的研究](https://jmlr.org/papers/v11/cawley10a.html)

### 4. 完整性检查必须严格

现有 `tools/cv_oof.py` 已有历史五折结果，可先审计来源，但不是当前544/KD完整配方的可直接替代品。工具目前允许缺折跳过，需改为以下任一失败便停止：

- 五折全部存在，每张训练图恰好一次OOF；患者不跨折。
- 预测键与标签一一对应，类别齐全、无重复、无缺失。
- 所有初始化、教师、学生的训练患者均排除对应outer-holdout。
- 端点、数据协议、预处理及最终聚合一致，源码/配置/权重有哈希。

同时报告逐折Δ、pooled OOF Δ及其差异，避免模型间概率尺度差异影响跨折排序。五个训练集高度重叠，不能把fold分数标准差除以√5直接解释为可信区间。

## 三、建议采用的采纳准则

目的应是最终检查级10类宏平均提高。原先“任意单类显著即可，整体允许下降0.001”的规则可能接纳真实总分更差的方案。

建议先写入实验登记表，再开跑：

1. 主终点唯一：最终聚合后的study macro ΔAUC。逐类和分组指标用于解释、守住明确底线。
2. baseline/candidate共享折表、训练seed、像素协议、预算及端点规则；一次只改变一个假设。
3. 用同一组患者整块重采样索引，对两版本计算配对Δ；建议5000–10000次，报告点估计及区间。固定预测的bootstrap不包含训练随机性，入围项再用第二个训练seed复核。
4. 预先限定候选数量，例如本轮3个主候选；多个确认检验可采用Holm校正。FDR可以用于发现候选，不宜作为最终只选一版的唯一依据。事后加校正也不能消除历次反复查看验证集的选择偏差。
5. 将“值得部署的最小收益”与“统计不确定性”分开。可讨论宏AUC +0.0005或+0.001的工程门槛，但它们是投入产出的选择，不是理论保证。
6. 探索阶段区间跨零不等于已证明无效；确认阶段若仍分歧，则保留当前版本，不把“没有证据变差”写成“等价”。不要仅因点估计为正就持续扩展搜索。

历史fold和官方valid已经反复使用；新的固定分工能减少进一步过拟合，但不能称它们是从未看过的新独立数据。

### Swin：历史已试过，先用旧资产做增量验证

`36_Swin跨架构_11-07.md` 中fold4加入Swin约+0.0010、区间包含0；`37_三成员集成_11-07.md` 记录全量部署study −0.0004、最终post-study −0.0012。过去的延迟瓶颈缓解，允许重新验证，但不能据此预期+0.002～+0.006。

39分钟来自 `v_swin512` 仅训练folds0/1/2的历史，约60%数据，不是全量时长。新配置要实测首轮再预算。

目标成员应明确为 **3 Tiny + Swin + B3 = 5**。不要直接把新增Swin与原Tiny等权；先预注册一个小权重候选，例如B3保持0.15、Swin0.05、3Tiny平分0.80。此例只是筛查起点，不是已推荐的最终权重，也不在test上搜索。

所谓“六模型”配置实际含6Tiny+B3，共7成员，现有浮点文件约711MB，超过500MB。其76.8ms只能说明该组合的本机耗时，不能证明新五成员一定合法。当前377.46MB加一个Swin预计接近489MB，需逐文件按必要配套实测；也需直接测五成员含JPEG的100图三轮端到端耗时。

### 差分：零初始化可以学，但没有训练安全保证

第一层额外通道零权重时，其梯度通常非零，因此不会天然“锁死”。第0步函数等价需要复制完整旧checkpoint、保留原首通道权重和bias、保持原首通道归一化及后续路径。仅从同一ImageNet初始化不等于当前最优模型。

训练开始后，原主干仍会更新，所以退化可能来自优化、增强、正则或信号尺度，不能全部归因“特征没用”。应加一个从相同checkpoint按相同新日程微调的控制组。

现有随机偏心裁剪会使图像中线偏离身体中线；侧位图也不适用左右对称的假设。先在AP/PA上定义一致的生成流程，侧位附加通道置零；若需调整增强，控制组也作相同调整。通道标准化不能改变原灰度通道。

第一次不要同时加入差分与高频后宣称“两项有效”。至少先比较控制、差分、高频三组；只有各自有证据，才考虑组合。还需同步checkpoint元信息、加载、TTA、CUDA Graph和cost入口，不能只改data/model两个函数。

### ROI：先定义一个可重复的完整算法

“热点×1.5”缺少热点范围和框大小定义；两个类别各取热点或四模型都重判，会增加多次前向。固定最多一个ROI和一个既有成员，明确定位图、框规则、最小尺寸、越界处理及融合方式。

如果目标是补细节，应从原始图像读取ROI；从512缓存裁放只是改变表示。原图解码、定位、裁剪和第二次前向都要计时。512+768两分支即使共享权重，按像素估算计算约为单512的3.25倍，不能从共享存储推导低延迟。

无定位真值时，不声称热图找到了正确病灶。评价全体正负样本的最终宏AUC及其配对差值，不用少量好看样例决定采纳。

## 五、预算与建议排期

五折4.8小时只是“一套单模型、每折一次训练”的粗略成本。baseline+一个candidate至少10次学生训练；两个candidate至少15次。采用折内双教师另需10次教师训练及软标签前向，可以复用但不能用全train软标签抵掉。筛查通过后还需要第二seed、完整部署验证及重训。

按当前历史速度，几十GPU小时的有控制试验可以安排在13天内；瓶颈主要是实现、证据完整性和交付余量。原来的“一次多通道训练便判断OOF增益”预算不足。

## 六、其他应修正的结论

- `p>0.9且标签负`为零不证明无标签噪声。KD和平滑可以压低概率，AUC也不依赖0.9阈值。审计可按OOF中每类的相对异常排序和跨模型分歧抽样；不能仅靠模型分数改标签。
- 同患者不同时点标签不同不等于自相矛盾，不能未经确认统一患者标签。
- “训练图片只有一次检查的患者20.9%”混用了图片/检查：数据画像里train只有1张图约20.9%，只有1个study约68.1%。
- 单张固定测试集的评分，在模型及评测固定时不因样本少而每天随机变化。136名患者限制的是对总体泛化的推断，不能把候选分差都称作平台随机噪声。
- 一次七成员略降，只说明本次组合没有增益，不能证明所有同构集成均无效；同理，跨架构也不保证增益。用配对增量和部署约束选择。
- 评审包写线上78.51，用户此前报告最终79.51，应与平台记录对齐；不要把分数冲突带入目标预算。本次不推定哪条记录有误。
