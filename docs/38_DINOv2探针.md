# DINOv2 表征探针：负结果（2026-11-22）

## 结论

**通用自监督表征（DINOv2 ViT-B/14，LVD-142M）在本任务上明显弱于现用 Tiny 的特征。**

主指标 **Δ1 = AUC(DINOv2) − AUC(Tiny 全局) = −0.0258**，远低于预注册门槛 +0.0150。
按预案**收口**：不再做第二折确认、不做蒸馏迁移。

---

## 一、实验设计（对抗审阅 §5 / §9 第 3–6 步）

| 项 | 内容 |
|---|---|
| 折 | 探索 **fold 2**：其余四折训练（14,807 检查），fold 2 留出评估（3,706 检查） |
| 画布 | 448×448（14 与 32 均可整除），两臂同解码、同 per-image 标准化 |
| 输入 | Tiny 收 1 通道；DINOv2 收灰度复制的 3 通道 |
| 两臂 | **A** = Tiny（`oof_f2/last.pt`）分类器前全局平均 768 维；**B** = DINOv2 最后 block 的 CLS 768 维 |
| 锚 | **R** = 现用原头（LSE 空间池化）在该折的实际分数 |
| 头 | 768→10 线性层，两臂同初始化（seed 20261120）、同批次顺序、AdamW(1e-3, wd 1e-4)、batch 64 检查、12 轮 |
| 标签 | **检查级硬 0/1**：图 sigmoid → 侧位 0.6 加权均值 → 检查级 BCE |
| 标准化 | 逐维均值/标准差**只用训练侧**估计，应用到两侧 |

权重来源：官方 `dinov2_vitb14_pretrain.pth` 与 HF `facebook/dinov2-base` 的
`model.safetensors`，两者均 330.3 MB；因 timm 的 HF 入口在本机不可用（`huggingface_hub.hf_api`
缺 httpcore2），改用自带的 ~80 行前向实现，键名逐条映射并做形状核对后 `strict=True` 加载。
**未使用任何医学预训练权重**（RAD-DINO 等）。

## 二、结果

| 臂 | 类 1 AUC | 宏 AUC | 十类 |
|---|---:|---:|---|
| **A** Tiny 全局特征 | **0.6386** | **0.7781** | 0.639 0.808 0.737 0.668 0.869 0.771 0.766 0.739 0.907 0.878 |
| **B** DINOv2 CLS | 0.6128 | 0.7351 | 0.613 0.763 0.698 0.603 0.827 0.719 0.741 0.686 0.856 0.846 |
| **R** 现用原头（LSE） | **0.6782** | **0.8103** | — |

- **Δ1 = B − A = −0.0258**（门槛 +0.0150）→ ❌ 未过门
- DINOv2 在**全部 10 个类别**上都低于 Tiny 特征，不是单一类的问题
- 两臂都低于现用 LSE 原头：说明**空间池化**（LSE）比"换个表征 + 全局平均"更关键

---

## 三、怎么读这个结果

**1. 这是"表征不是瓶颈"的直接证据。**
我们此前的假设是：类 1（纵隔心影增大，OOF 0.695）可能是因为 Tiny 的监督 ImageNet 特征
缺少某种信息，换成自监督大规模表征也许能补上。结果相反 —— 通用表征明显更差。

**2. 但要注意比较的边界。**
- A 与 B 都是**线性头 + 全局平均**，这是同协议对照，Δ1 有效。
- R 用的是 LSE 空间池化 + 任务训练的特征，与 A/B 的**头结构不同**，
  所以 "R 更高" 不能完全归因于特征更好，也包含池化方式的差异（这正是我们此前发现
  LSE 有效的原因）。

**3. 类 1 的问题更像标签定义问题，不是表征问题。**
合并三条独立证据：
- 官方类 1 = 纵隔心影增大，文献中阳性一致率最低；
- 换表征（DINOv2）不改善，反而更差；
- 换训练目标（患者平滑 0.30→0.10）、换输入通道（对称差分）也都不改善。
