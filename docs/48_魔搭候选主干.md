## 二、先用许可证过筛（这一条最容易踩坑）

- **`cc-by-nc-4.0` 是非商用**：ConvNeXtV2 全系都在此列。比赛虽非商业行为，但交付材料要声明来源，
  非商用许可会引入解释空间 —— 建议**排除**。
- 干净可选：CAFormer（apache）、MaxViT（apache）、CoatNet（apache）、EVA-02（mit）、SwinV2（mit）。

## 三、我们自己的证据先摆出来（避免重复踩坑）

| 已测 | 结论 |
|---|---|
| ConvNeXt-Tiny → **Small**（12 轮同配方） | −0.008 |
| ConvNeXt-Tiny → **Base** | 更差 |
| 加 **Swin-T** 作第 5 成员（5% 权重） | −0.0002 |
| 换 **ImageNet-22K** 预训练 | −0.0016（类 2 −0.019，类 8 +0.005） |
| 换 **DINOv2** 通用自监督表征（冻结特征） | 十类全低；类 1 −0.0258 |

⇒ **"更大的容量"和"更强的通用表征"这两条轴，我们都已实测为负。**
再选模型的唯一理由是：**归纳偏置不同**（不是更大）。

## 四、结论与建议

### 推荐（若要试，只试一个）

**CAFormer-S18（`timm/caformer_s18.sail_in22k_ft_in1k`，apache-2.0，24.3M）**

理由：
1. 参数量与我们 Tiny **几乎相同**（24.3M vs 27.8M），算力同量级 ⇒ 100 ms 预算仍可容纳；
2. 预训练范式不同（MetaFormer + SAIL 蒸馏 + IN22K），提供**真正不同的误差结构**；
3. 许可证干净（apache-2.0），交付风险最低。

### 不推荐

| 候选 | 原因 |
|---|---|
| ConvNeXtV2 全系 | CC-BY-NC 非商用许可 |
| EVA-02-B/448 | 448 输入 + 86M 参数，单张远超 100 ms，只能替换整个系统，风险最大 |
| MaxViT-S、CoatNet-1 | 算力/延迟吃紧，收益不确定 |
| MobileNetV4、EfficientViT-B1、RepViT | 容量低于现基线 |

### 如果要动手，最小验证路径（不推翻现有交付）

1. 折：**fold 2**（探索折，与 DINOv2 探针同一折，可直接比）
2. 配方：与我们 Tiny 完全一致（12 轮、544 输入、KD 0.5、患者平滑 0.3、LSE 0.30）
3. 通过线：**OOF 折 2 的检查级宏 AUC ≥ 0.8200**（现 Tiny 在该折约 0.814–0.816）
4. 成本：约 **2–3 GPU 小时**（CAFormer 在 544 下约为 Tiny 的 3–4 倍算力）
5. 若通过 → 再跑剩下四折（约 10–12 小时），否则收口

> 提醒：我们的 ensemble 已是 4 成员 377 MB / 51 ms。任何新主干若要与现有成员**并联**，
> 都要先算体积与延迟；并联导致超限时只能**替换**现有成员，那会动到已验证的 78.51。

## 五、工程风险（必须先确认）

新架构接入有三处需要适配，不能假定直接可用：
1. **单通道输入**：`_adapt_first_conv` 目前只处理"第一层是 3 输入卷积"的情形，
   CAFormer/MaxViT 的 stem 命名与结构不同；
2. **LSE 头**：需要模型能吐出**空间特征图**（预分类器），ViT 族需改造；
3. **混合精度 + CUDA Graph**：新的算子图可能无法捕获（我们已有 fallback，但会掉延迟）。
