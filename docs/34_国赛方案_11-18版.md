# 国赛方案（截止 2026-12-01）

> 前提：**数据集不变** —— 数据、缓存、六个权重、代码全部可直接复用，不需要重下 55 GB，
> 也不需要重建缓存（`cache/train_512.npy` 等已在本地）。
> 距截止 **12 天**，单卡 RTX 4090D，一次 Tiny 训练 **≈ 57 分钟**。

---

## 一、先确认两件事（决定后面一切）

| 待确认 | 为什么关键 |
|---|---|
| **test 集是否还是同一批 2,218 张图** | 若是，起点分就是 78.51，且线上反馈仍受 136 名患者 / ±0.3 噪声限制；若不是新图，则所有离线结论需要重估 |
| **每天允许提交几次、有没有 valid 反馈** | 1 次/天 + 无反馈 = 只能靠离线尺子决策，不能靠线上试错 |

两种情形都能执行下面的方案，但"是否值得冲 +0.005"的判断不同。

## 二、方案清单（按 ROI 排序）

### 阶段 0：零成本/低成本，今天就能做完

#### 0.1 六模型集成（**已实测，结论：无增益，不要做**）

现有 6 个 ConvNeXt-Tiny：3 个原始种子 + 3 个重训种子。已在 2026-11-18 实测：

| 项 | 四成员（交付版） | **六成员** | 结论 |
|---|---:|---:|---|
| valid mean AUC | 0.8313 | **0.8311** | **−0.0002，无增益** |
| 单张端到端 | 51 ms | **76.8 ms**（p95 86.6） | 延迟 +26 ms，仍在 100 ms 内 |
| 与四成员的全表 Spearman | — | **0.99928** | 几乎同一组预测 |

**原因**：重训种子与原始种子是"同一配方 + 不同 cuDNN 抖动"，本质是同一个模型的两次抽样
（见 `30_重训复现.md`）。**集成收益来自多样性，不来自成员数。**

**替代做法（这才是有增益的方向）**：补一个**跨架构**成员。实测过的训练成本：

| 候选 | 12 轮耗时 | 历史表现 |
|---|---:|---|
| **Swin-T @512** | **39 分钟**（最快） | 单模较弱，但与 ConvNeXt 相关性低 |
| ConvNeXt-Small @512 | 106 分钟 | 单模 −0.008，历史作第 4 成员时被延迟否掉 |
| EfficientNet-B0 @384 | 40 分钟 | 单模明显更弱 |

赛季内"跨架构供体（EfficientNet-B3）"是四个有效方法之一，说明这条路成立。
现在有了 CUDA Graph，延迟余量（76.8 → 还有 23 ms）足以容纳一个 Swin-T。

| 项 | 内容 |
|---|---|
| 实现 | 训练 Swin-T@512（39 分钟）→ 加入成员，权重与其他 5–6 个均分，供体保持 0.15 |
| 成本 | **约 2 小时**（训练 39 分钟 + 评估 + 打包） |
| 预期 | +0.002 ~ +0.006（历史跨架构成员的同类量级） |
| 判定 | OOF 配对 bootstrap 下界 > 0；延迟实测 < 100 ms |

#### 0.2 双口径评估工具

把已经验证过的三口径逻辑（plain / patient / test-like）封装成 CLI，
以后每个实验都同时看三个数。文件已存在：`tools/patient_structure_impact.py`。

| 项 | 内容 |
|---|---|
| 成本 | 0.5 小时 |
| 用途 | 防止再次出现"valid 上涨、test 结构下不涨" |

#### 0.3 逐类收缩系数（10 个参数，零训练）

现在全局用 `shrink = 0.85`。但不同类别对患者先验的依赖不同（类 8 实变在患者内高度相关，
类 1 肺不张常为单次即发）。改成每个类一个系数 `a_c`，在 OOF 上拟合。

| 项 | 内容 |
|---|---|
| 实现 | 提交构建阶段（`tools/make_submission_long.py` 风格）按类施加不同 shrink |
| 成本 | 1 小时（10 个参数在 11k 患者上拟合，不易过拟合） |
| 预期 | +0.001 ~ +0.003 |
| 判定 | OOF 上 test-like 口径不得下降 |

### 阶段 1：把尺子做准（必做，否则后面全是盲试）

#### 1.1 五折 OOF 评估集

| 项 | 内容 |
|---|---|
| 实现 | 按患者分 5 折训练，每折在留出折上预测，拼成 30,344 张的 OOF |
| 成本 | **5 × 57 分钟 ≈ 4.8 小时** |
| 收益 | 类 1 阳性患者 16 → **约 572**，SE 0.067 → **0.011**，最小可测差异 0.168 → **0.03** |
| 用途 | 后面每个改动的唯一裁判；同时给出每类 AUC 的分布而非单次抽签 |

---

### 阶段 2：结构性先验（本项目唯一有效的一类方法）

核心技巧：**新增通道零初始化** —— 新通道的卷积权重初始化为 0，
模型在第 0 步与当前最佳**完全相同**，之后只在不伤害原信号的前提下学习使用新特征。
这样任何退化都能归因于"这个特征没用"，而不是"改坏了初始化"。

#### 2.1 左右对称差分通道（针对类 1 肺不张）

| 项 | 内容 |
|---|---|
| 机理 | 肺不张的本质是**单侧体积缩小**。`asym = |I − fliplr(I)|` 直接把这一定义变成输入 |
| 实现 | ① `src/cxr/data.py`：增强后计算 `asym`，与灰度图堆成 2 通道；② `src/cxr/models.py::_adapt_first_conv` 改为接受 `in_ch=2`，新通道权重初始化为 0 |
| 成本 | 1 次训练 57 分钟 + 改代码 1 小时 |
| 预期 | 类 1 **+0.02 ~ +0.04**（若成立，整体 +0.002~0.004） |
| 判定 | OOF 上类 1 的配对 bootstrap 下界 > 0 |

#### 2.2 高频细节通道（针对类 1、类 4）

| 项 | 内容 |
|---|---|
| 机理 | 肺不张的盘状影、浸润的网状影都是高频结构；512 缩放会削弱它们。`high = I − blur(I)` 作为第二通道显式提供 |
| 成本 | 1 次训练（可与 2.1 合并成一个"多通道输入"实验，一次训练测两个特征） |
| 预期 | 类 1/4 各 +0.01 ~ +0.02 |

#### 2.3 4↔8 软标签（针对类 4 浸润、类 8 实变）

| 项 | 内容 |
|---|---|
| 机理 | P(实变 | 浸润) = 0.529，两种病变影像上连续。训练目标互相软化：`y4' = 0.85y4 + 0.15y8`，`y8' = 0.85y8 + 0.15y4` |
| 注意 | **合并两类已被实测排除**（合并预测后两类都变差）；软标签不同——它保留两个独立头，只放宽目标 |
| 成本 | 1 次训练 |
| 预期 | 类 8 +0.01 ~ +0.02（全项目 AUC 最低的类，0.748） |

### 阶段 3：推理侧（零训练）

#### 3.1 热图局灶重判（针对类 5 结节、类 8 实变）

| 项 | 内容 |
|---|---|
| 机理 | 用模型自己的 LSE 证据图 `M[b,c,h,w]` 找到最热区域，围绕它裁 1.5× 区域 → 缩放 384 → 再前向一次 → 与原预测加权平均 |
| 成本 | 推理 +12~20 ms（51 → 70 ms，仍 < 100 ms）；开发 2 小时 |
| 预期 | 类 5/8 各 +0.01 左右 |
| 风险 | 双阶段误差累积；必须在 OOF 上验证，不能只看个例 |

### 阶段 4：高风险高回报（有余力再做）

| 方案 | 机理 | 风险 |
|---|---|---|
| **把 valid 并入训练** | 规则第 3 条允许；valid 有 228 名患者 / 1,422 张，约 +4.7% 数据。只用 OOF 选模 | 失去唯一官方有标签评估集；一旦 OOF 与官方口径不一致就无处校验 |
| **标签审计** | 用 OOF 找出"模型高置信度却与标签相反"的样本，人工看 20 张，判断是否存在系统性标注噪声 | 若确认噪声，处理方式（软标签/剔除）本身要验证，12 天内风险偏高 |

### 明确不做的（有实测理由）

| 不做 | 理由 |
|---|---|
| 合并类 4 与 8 | 实测合并后两类都变差 |
| 类别加权 / 过采样 / ASL / Focal | 赛季内全部无效 |
| 换更大骨干（Small / Base） | 全部更差 |
| 逐类融合权重 | 样本内正、跨折负 |
| 继续扫分辨率 / 池化参数 | 已扫到边际收益为 0 |
| 单独优化类 1（在 valid 上） | 24 个 study，最小可测 0.168 |

## 四、止损规则（提前定好）

1. 任何改动必须过 **OOF 单类配对 bootstrap 下界 > 0**，否则视为无效。
2. 整体 10 类平均 AUC 不得下降超过 0.001。
3. **连续两个方法未过门 → 停止该方向**，把时间转到组合与稳定性上。
4. D9 之后不再改模型，只做打包与验证。
5. 每天只提交一次，且**每次提交前先跑一遍 `tools/audit_official_feedback.py`**。

## 五、现实预期

数据集没变，意味着**信息上限没变**。上面所有方案的总和，乐观估计
**+0.01 ~ +0.02 离线 AUC**（主要在类 1/4/8）。换算到线上，考虑 ±0.3 的噪声，
**大概率仍落在 78.5 ± 0.3**。

所以国赛真正值得投入的不是"再找 0.01"，而是：

1. **把评估做对**（五折 OOF + 双口径）—— 让每个决定有依据；
2. **把交付做稳**（提前打包、提前审计、留缓冲）—— 不再在最后一天修 bug；
3. **把结论写清**（哪类能改、哪类改不动、为什么）—— 这本身是评审看重的东西。
