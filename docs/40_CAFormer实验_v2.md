## 二、四处更正（逐条核实）

### 更正 1：多样性被高估 —— 旧数字只用了类 1

**旧版**：`e1_score.py` 里写的是 `pd.Series(cand[1])`，只取**类 1**（纵隔心影增大）的排序相关，
对三个 Tiny 求平均得 **0.866**，据此判定"多样性达标"。

**修正**：逐类算 Spearman 再取平均 → **0.9245**（展平所有类为 0.9610）。

| 对比对象 | 逐类均值 | 展平 |
|---|---:|---:|
| vs `cnxt512_pat_e12` | 0.9231 | 0.9610 |
| vs `cnxt512_pat_s43_e12` | 0.9245 | 0.9616 |
| vs `tiny_seed44_last12` | 0.9259 | 0.9623 |
| **均值** | **0.9245** | 0.9616 |

⇒ CAFormer 与 Tiny **并不比 Tiny 之间（0.95）多样多少**，多样性一项**不成立**。

另：预测排序相关性不等于"误差结构"。它只是各成员对同一批样本的相对排序相似度，
不能直接推断误差的来源或可互补性。v1 用"误差结构不同"表述不严谨。

### 更正 2：融合顺序与部署不一致

**旧版**：先把每个成员做检查聚合 + 患者收缩，再做 half_power 融合。
**部署实际**：**逐图融合 → 检查加权均值 → 患者收缩**。half_power 是非线性的，两者不可交换。

**修正**：改为逐图融合。同时修正替换测试的权重错误 ——
旧版把候选设为 1.0 后归一（等于给了 50%），实际应**精确占据被移除 Tiny 的 0.283333**。

修正后的结果：

| 形态 | 参数 | Δ 宏 AUC |
|---|---|---:|
| 添加 | w=0.05 | **−0.000129** |
| 添加 | w=0.10 | −0.000345 |
| 添加 | w=0.15 | −0.000666 |
| 添加 | w=0.20 | −0.000957 |
| 替换（原权重 0.2833） | 去掉 `cnxt512_pat_e12` | −0.001549 |
| 替换（原权重 0.2833） | 去掉 `cnxt512_pat_s43_e12` | −0.001605 |
| 替换（原权重 0.2833） | 去掉 `tiny_seed44_last12` | −0.001757 |

**方向不变（仍为负），但幅度与旧版不同，旧版的 −0.0041~−0.0045 作废。**

### 更正 3："配方完全一致"不成立

| 维度 | CAFormer | 旧 OOF Tiny（oof_f2） | 交付 Tiny |
|---|---|---|---|
| 输入尺寸 | **544** | 512 | 544 |
| 训练数据 | **80%（其余四折）** | 80% | **100%** |
| 蒸馏 | **无** | 无 | **有（KD 0.5）** |

所以"同配方"只在"无 KD + 80% 数据"这一层成立，**输入尺寸 544 vs 512 也不同**。

更接近的同类对照：无蒸馏 Tiny 在同一 valid 上 **0.81435**，CAFormer **0.80077**，差 **0.0136**。
差距是真实的，但**不能把全部差距归因于架构** —— 分辨率、预训练范式、训练稳定性都可能贡献。

### 更正 4：不能由两个例子推出淘汰规则

v1 写"单模比现有成员差不超 0.01 才可能被吸收"，依据是供体（弱 0.006 → +0.0041）与
CAFormer（弱 0.018 → −0.0002）两个点。**两点不足以支撑一条规律**。

正确表述：

> "单模差距 ≤0.01" 只能作为**人为预算规则**（用于决定是否值得花 GPU 时间），
> 不是实验证明的规律。反例随时可能出现，尤其当多样性远高于供体时。

同理，"KD 最多补 +0.011"也是**一个观测值**（Tiny 从 0.8125→0.8231），**不是上界**。
不同架构从 KD 获益的幅度未测。

**因此：不能仅凭 SwinV2 的单模分数就跳过集成评估。**
好在逐图概率已有，CPU 融合比较的成本极低（秒级），没有理由省这一步。

## 三、基线核对（必须说明的限制）

用成员逐图概率按部署口径重算，集成基线为 **0.82535480913**，
而冻结包记录是 **0.82519454845**，**差 +1.60e-04**。

⇒ 本次所有 Δ 都是**同一套缓存内的配对比较**，方向可信；
但绝对数值与冻结包不一致，**不能当作最终部署验收**。
差的来源尚未查清（此前已确认：cache 448 给 0.824966、cache 512 给 0.825355、冻结值 0.825195 两者都不是）。

## 四、修掉的工程问题（6 项）

| # | 问题 | 现象 | 修法 |
|---|---|---|---|
| 1 | CAFormer 不接受 `img_size` | `TypeError: unexpected keyword argument 'img_size'` | try/except 回退默认构造 |
| 2 | **`train.py` 未向 `build_model` 传 `img_size`** | SwinV2 按 256 构造 → 喂 512 断言失败 | 补参数 + `set_input_size` 兜底 |
| 3 | 云端连不上 huggingface.co | 卡在 `Retrying`，GPU 0% | `CXR_WEIGHTS_DIR` 本地权重 + 从魔搭自动拉取 |
| 4 | 打包时缓存索引 JSON 为 0 字节 | `json.load` 报 `Expecting value` | 从源目录取 + 打包前后硬校验 |
| 5 | 日志被 stdout 缓冲 | 看起来"卡住" | `python -u` + `PYTHONUNBUFFERED=1` |
| 6 | **判读脚本三处口径错误** | Spearman 只取类 1；融合顺序与部署不一致；替换权重给成 50% | `../tools/e1_score_v2.py`（本报告使用的版本） |
