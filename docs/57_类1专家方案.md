# 类 1 专家模型方案（2026-11-26 · 修订版 v2）

> v1 有四处会被误执行的问题，已被评审指出并全部改正：
> ① T3b 入口自相矛盾；② 迁包门槛写成"不跨 0"（含显著为负）；③ 用错基线人群算杠杆；
> ④ 实现顺序会导致"新头拿到随机权重 + 主干仍带 dropout"。
> 另新增**一个 1 参数的廉价对照**（评审 B）：它可能用 1 个标量就解释掉全部收益。

## 一、为什么只盯类 1

| 项 | 值 | 说明 |
|---|---|---|
| 类 1 官方名 | 纵隔心影增大 | |
| **单只 Tiny 的五折 OOF AUC** | **0.6955** | 十类最低（类 4 = 0.7327，类 8 = 0.7540） |
| **交付集成在官方 valid 的类 1 AUC** | **0.767315** | 主基线，**逐图融合后聚合**（固定口径） |
| **fold2 上 Tiny 的类 1 AUC** | **0.676230** | T3a 的真正对照人群（2,211 患者） |
| 训练阳性 | 719 图 / 622 检查 / 572 患者 | |
| fold2 留出阳性 | 119 检查 / **114 患者** | **主终点** |
| 官方 valid 阳性 | 35 图 / **24 检查** / **16 患者** | 区间宽约 0.25，**只作旁证** |

### 一个必须讲清的算术

`0.6955 → 0.75`（宏 +0.0055）**不是这套系统的空间**：

- 0.6955 是**单只 Tiny** 的五折 OOF，不是交付集成的水平；
- 交付集成在 valid 上类 1 已是 **0.767315**；
- T3a 的新头在融合里**只占 16%**（旧头 64% + 新头 16% + CAFormer 20%）。

⇒ 融合后的类 1 要涨 0.010，**新头自己得比旧头好出一截**。判读必须分两行：

| 行 | 含义 | 用途 |
|---|---|---|
| **行 1** | 新头单独 vs 旧头的类 1 Δ | 诊断：头到底学到了什么 |
| **行 2** | 按 16% 掺进融合后的类 1 Δ | **唯一用于升级决策** |

## 三、三组对照（本次核心改动）

全部使用**同一批冻结空间特征**、同一套逐图融合与检查聚合：

| 组 | 可训练参数 | 能回答的问题 |
|---|---:|---|
| **G0 原头** | **0** | 现有类 1 排序是多少（对照） |
| **G1 只学偏置** | **1** | 只调整概率水平，融合能拿到多少收益 |
| **G2 完整共享头** | **769** | 重新学习 768 个通道权重，能否在 G1 之上进一步改善排序 |

**只有 G2 在另一折仍超过 G1，才能把收益归给"特征重加权"。**
若 G2 ≈ G1，**一个标量就能实现同样效果** —— 那就没有专家，只有一个校准项。

先固定这三组，**不扫学习率、不扫融合权重**。

## 四、实现规格（v1 的顺序是错的，这里写死）

### 4.1 正确的执行顺序

```
1. build_model（会随机初始化头）
2. 载入该折 last.pt          ← 必须在前
3. 复制**已训练**的类 1 权重/偏置到新头（G2）或复制 W[0] 到偏置（G1）
4. model.eval() 并保持       ← 不是只设 requires_grad=False
5. 冻结除新头外的全部参数
6. 每轮**不要**调用 model.train()
```

**为什么第 3 步必须在载入之后**：在模型构造时复制 `W[0]`，拿到的是随机初始化的权重。
**为什么第 4 步必须是 `eval()`**：`_forward_lse` 在 `training` 时对通道做 dropout
（`keep = rand >= p_drop`），头会在 dropout 后的特征上学习，而推理时 dropout 关闭 ——
训练与验收不是同一条特征。`requires_grad_(False)` 不会关掉 dropout 与随机深度。

### 4.2 标签

直接用**原始类 1 硬标签**，并显式关闭：

- 患者平滑（`--patient-smooth 0`）
- 标签平滑（`--label-smooth 0`）
- 蒸馏（`--distill-weight 0`）

否则沿用 Tiny 配方时，`data.py` 第 108 行起可能已把目标改成软标签。

### 4.3 接入检查（六项，全过才开跑）

| # | 检查 | 期望 |
|---|---|---|
| 1 | 新头初始化后与旧类 1 输出 | 逐位相等（差 0） |
| 2 | 冻结后主干与旧头参数梯度 | 全部为 `None` |
| 3 | 可训练参数个数 | G0 = 0 / G1 = 1 / G2 = **769** |
| 4 | 训练 50 步后**新头权重** | **确实变化**（差值 > 0） |
| 5 | 训练 50 步后**原模型权重** | **完全未变**（差值 = 0） |
| 6 | 同一前向里其他九列 | 与旧头输出**逐值相同** |

**第 6 项不要去比历史导出的 CSV** —— 同一套权重重新推理已经出现过 **9.2e-3** 的差。
九列必须取**这次前向里的旧头输出**，只换第 0 列。

## 五、决策规则（预注册，跑之前定稿）

### 5.1 fold2 决定「值不值得花 fold3」

主读数是 **行 2**（16% 掺入后的融合类 1 Δ），点估计与患者级配对区间都报。

| 情形 | 处置 |
|---|---|
| 点估计 ≥ **+0.005**（⇔ 宏 ≈ +0.0005）**且**其他九列差 = 0，但区间跨零 | 记为「**待确认**」，可再花一次小头训练的钱去 fold3 |
| 点估计 ≥ +0.005 **且**区间整段 > 0 | 直接进 fold3 |
| 点估计 < +0.005 | 不进 fold3（省下预算） |

> +0.005 这个数对应"团队认为宏 +0.0005 值得追"。要在**看训练结果之前**定稿。

### 5.2 fold3 判断「收益能否重复」

- 换用 **fold3 自己的 Tiny** 起点；
- 需要 fold3 的 CAFormer 概率 —— **当前没有**（我们只有 fold2 的）。
  若 CAFormer 最终不进包，**不要把 20% 的 CAFormer 焊进唯一读数**，改为只在同折 Tiny 上比。

### 5.3 迁移到交付包的门槛（v1 写太低，已改）

| v1（错） | v2（正确） |
|---|---|
| Δ > 0 且「区间不跨 0」 | **融合后类 1 Δ ≥ +0.010 且患者级区间整段 > 0** |

理由：类 1 只占宏的 1/10 ⇒ **+0.003 的类 1 增益只值宏 +0.0003**，
**不值得动一个已经冻结、线上有效的包**。fold3 可以只按方向复跑（5 分钟成本），
但迁包必须用**与 T3b 同一条 +0.010**。

### 5.4 T3b（独立专家）另立实验，且入口互斥

v1 写的"Δ ≥ +0.010 且训练饱和"**无法同时成立**，删掉。改为两条互斥出路：

| 观察 | 含义 | 处置 |
|---|---|---|
| **融合后类 1 Δ ≥ +0.010 且区间整段 > 0** | 头有效 | **只迁移这个头，不训 T3b** |
| **训练损失明显下降，但 fold2 的 Δ 仍跨 0 或为负** | 固定特征不够 | **此时才讨论 T3b**，且先验仍然低 |

**T3b 的一个必查项**：一只只输出类 1 的专家若**替换**原 Tiny，
会同时移除原 Tiny 对另外九类的贡献 ⇒ **必须重算十类宏 AUC**，不能再用"类 1 Δ ÷ 10"估算。

## 六、这个方案**达不到**的

1. 改不了标签定义 —— 纵隔增宽本身判读一致性就差。
2. 救不了 valid 的 16 名阳性患者 —— valid 只作旁证，**fold2 的 114 名才是主终点**。
3. 不解决类 4（0.7327）/ 类 8（0.7540）—— 不按首折读数临时拼装专家。
4. 不是"重增强 + 32 轮"那条路 —— 在 T3a 证明"固定特征不够"之前不投入。

## 七、成本（必须实测，v1 的"5 分钟"是猜的）

| 项 | v1 说法 | v2 做法 |
|---|---|---|
| 参数量开销 | "0 MB" | 769 × 4 = **3,076 字节**；但仍有一次**空间投影 + 池化** |
| 延迟 | "0 ms" | 复用主干，新增一次 1 通道 einsum + LSE，**需实测** |
| 训练时长 | "5 分钟" | 24,194 图 × 3 轮在 5 分钟内完成，需要 **≈242 图/秒** —— **先测 50 个真实训练步** |

**若考虑缓存冻结特征**：必须保留**空间特征图**（B×C×H×W）。
只存全局均值会丢失重算 LSE 所需的空间信息。缓存 768×17×17 的 fp16 特征约
`24,194 × 768 × 17 × 17 × 2 B ≈ 10.7 GB`，需先确认磁盘。

| 步骤 | 估时 |
|---|---:|
| 实现（模型 + 冻结 + 导出） | 1 h（CPU） |
| 接入六项检查 | 15 min（GPU） |
| 50 步吞吐实测 | 3 min |
| G0/G1/G2 三组 × 3 轮 | 由实测吞吐决定 |
| fold2 评估 + bootstrap | 10 min（CPU） |
